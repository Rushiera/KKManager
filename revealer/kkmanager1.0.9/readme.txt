KK Manager by Rushiera —— 发布版 1.0.9
======================================================================

【本版更新】（发布版 1.0.9 · 对应编译版 0.20.5）
  · 扫描前先弹配置窗——步骤自己勾、顺序自己定（卡片行 / 角色名 / 声明区（必选）/ 概览 /
    服装槽位 / 时间轴 / 卡片分析…）；分项各自落库，没勾的步不跑
  · mod 库扫描面放宽——库根（含子目录）内全部文件逐个尝试读 manifest.xml：
    `.zip` 等任何扩展名的 zip 容器都收（此前只认 `.zipmod`）；读不到的判「非 mod 文件」出声
  · 新增「插件库」（BepInEx）——库根设置里预置锁定只读行（在 mod 主库上方）；
    顶栏「插件清单」列出每个 dll 里的插件（名 / GUID / 版本 / 进程过滤）；
    打开时显示上次启动实况（待加载 / 已加载 / 进程过滤跳过 / 错误）；
    场景卡的插件键可对着已装插件查（`kkpe` / `timeline` / `vnge_*`）
  · 新增「待办清单」——顶部统计卡「待办」点入：库已离线 / 卡片 / 手输三类分支；
    卡片页「引用明细」里可给这张卡「加待办」（一卡可多条）；手输为纯文本、同内容重复拒绝；
    只做新建与关闭
  · 新增「非卡 / 非 mod」清单——不是卡片也不是 mod 的文件单独成表（卡图 / 理由 / 文件位置，
    点位置在资源管理器里选中）；底栏「一键移到缓存库」搬走即出清单；
    无数据区的纯图片改判「非卡 · 无数据区（纯图片）」（此前报读取失败）
  · 修复：库里 mod_count 为空时卡片列表整页报错 · 场景卡空轴 timeline 误报「长度越界」·
    卡片库根被误判为只读（卡片侧的非卡文件搬不动）
  · 读面提速与稳定：时间轴 / 服装槽位 / 卡片分析 / 场景深度四步共用同一文件句柄
  · 命令行同步：新增 `scan-plan` / `todos` / `todo-add` / `todo-close` / `noncards` /
    `noncard-move` / `plugins` / `plugin-match` / `plugin-log` / `plugin-info` / `scan-plugins`

【做什么】
  把「这张卡用了哪些 mod / 缺哪个 / 对应本地哪个文件」从人肉比对变成可查询的数据库。
  卡片（.png 人物卡 / 服装卡）与 mod（.zipmod）的关联按 mod 内部标识（guid）判定——
  mod 文件被改名也不影响关联，文件名只作给人看的线索。

【怎么用】
  1. 双击 KMR.exe —— 面板会在浏览器自动打开（默认 http://127.0.0.1:8539）
  2. 第一次使用：点顶部「库根设置」→ 设置游戏根目录（Koikatsu 安装目录）→ 保存
     （mod 主库 / 缓存库 / 卡片库根会按游戏根自动填入，均为锁定行）
  3. 点「扫描 mod 库」「扫描卡片库」——首扫较慢（本机 1 万个 mod 约 1 分钟量级）
  4. 之后在卡片列表 / mod 列表 / 缺失清单 / 统计卡之间查看关联与缺失

  关于扫描范围：
    · 库根由你自己添加与掌管，软件不自动遍历游戏根下的全部目录
    · 扫描范围 = 你添加的文件夹地址；不需要的目录不要加
    · 卡片库根可加多条（附加库）；mod 侧新增的库根默认是「冷冻库」（只读归档）

【数据在哪】
  data\kkmanager.db —— 本软件自己的数据库，与游戏文件无关（首次运行自动创建）
  想回到初始状态：双击「清空所有数据.bat」（两次确认；不备份，删掉恢复不了）

【运行要求】
  Windows 10 / 11 64 位 · 无需安装 .NET 运行时（运行时与全部依赖已随本程序打包）
  首次启动需解出原生库，稍慢属正常

【注意】
  · 本程序只读卡片与 mod 文件——不会改动它们（卡片编辑需在面板内单独授权后才可用）
  · 不下载 mod——缺失项只做定位提示
  · 本版本为发布版，内容冻结：升级请整包替换，不要单独替换其中文件
